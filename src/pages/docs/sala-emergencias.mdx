# Sala de Emergencias: Guía de Rescate Técnico

Los imprevistos ocurren: mensajes mal redactados, cambios en la rama incorrecta o conflictos inesperados. Git está diseñado con total integridad y mecanismos redundantes para que casi todo sea corregible y enmendable si conoces los comandos adecuados.

---

## 1. Editar un mensaje de commit recién hecho: `git commit --amend`

Si acabas de confirmar un commit (*commit*) en tu repositorio local pero notaste que escribiste mal el mensaje o necesitas añadir un archivo de último minuto, puedes modificar esa última instantánea directamente:

```bash
git commit --amend -m "feat: corregir mensaje del commit anterior"
```

Si querías agregar un archivo que olvidaste, añádelo primero al área de preparación (*staging area*) con `git add` y luego ejecuta el comando `--amend` para actualizar la confirmación actual.

---

## 2. Reubicar un commit hecho en la rama equivocada: `git cherry-pick`

Si creaste una confirmación de forma accidental en una rama errónea, puedes "pescar" y aplicar ese cambio individual en tu rama correcta utilizando su hash SHA-1 de 40 caracteres:

```bash
# 1. Muévete a la rama donde DEBIÓ guardarse el cambio
git checkout rama-correcta

# 2. Aplica los cambios de esa confirmación específica
git cherry-pick a1b2c3d4e5
```

---

## 3. Guardar cambios temporalmente sin hacer commit: `git stash`

Si necesitas cambiar de contexto urgentemente para solucionar un error de producción, pero tu directorio de trabajo (*working directory*) está a medio desarrollar y no quieres crear un commit incompleto, guarda tus cambios en un baúl temporal:

```bash
git stash
```

Tu directorio de trabajo quedará limpio. Cuando soluciones la emergencia y desees recuperar tu trabajo pendiente para continuar, ejecuta:

```bash
git stash pop
```

---

## 4. Eliminar un archivo del seguimiento de Git (Interacción entre `.gitignore` y `git rm --cached`)

Añadir un archivo al archivo `.gitignore` no impedirá que Git continúe rastreándolo si ya lo habías confirmado en el pasado.

Para indicarle a Git que deje de seguir el archivo en su índice (*index*) **sin eliminar el archivo físico de tu computadora**, ejecuta:

```bash
git rm --cached config/variables-secretas.env
```

Luego, añade la regla en tu archivo `.gitignore` para evitar volver a agregarlo por error:

```bash
# Agrega el archivo a la lista de exclusión
echo "config/variables-secretas.env" >> .gitignore

# Confirma el cambio del .gitignore
git add .gitignore
git commit -m "chore: remover del seguimiento el archivo env e ignorarlo en .gitignore"
```

---

## 5. Entender y resolver un Conflicto de Fusión (*merge conflict*)

Un conflicto de fusión (*merge conflict*) se genera si dos ramas modifican la misma línea de un archivo y Git no puede resolver automáticamente cuál conservar.

Cuando esto pasa, Git detiene la fusión y marca el archivo en conflicto con indicadores visuales. Al abrir el archivo conflictivo, verás lo siguiente:

```text
<<<<<<< HEAD
Tus cambios locales de la rama activa (donde estás posicionado)
=======
Los cambios de la otra rama que intentas fusionar
>>>>>>> feat/nueva-vista
```

### Resolución paso a paso:
1.  **Inspecciona:** Analiza ambas opciones y conserva la correcta.
2.  **Limpia:** Elimina manualmente los marcadores `<<<<<<<`, `=======` y `>>>>>>>`, dejando únicamente el código final deseado.
3.  **Finaliza:** Agrega el archivo corregido al área de preparación (*staging area*) y realiza la confirmación de fusión para cerrar el conflicto:
    ```bash
    git add archivo-corregido.js
    git commit -m "merge: resolver conflictos de fusion en archivo-corregido"
    ```

---

## 6. Deshacer el Historial: `git revert` vs. `git reset`

Si necesitas deshacer un cambio del historial de confirmaciones, debes elegir cuidadosamente entre estas dos herramientas:

*   **`git revert` (Seguro y colaborativo):** Crea un **nuevo commit** que revierte de forma exacta los cambios introducidos por un commit anterior. No borra ni modifica tu historial existente, lo que lo convierte en el comando estándar y seguro para repositorios compartidos en GitHub o GitLab.
    ```bash
    git revert a1b2c3d4e5
    ```
*   **`git reset` (Destructivo para historial):** Mueve la punta (*tip*) de tu rama hacia atrás, omitiendo o descartando commits del historial. Como reescribe el historial de confirmaciones, **nunca** debe utilizarse en ramas compartidas en plataformas remotas.
    ```bash
    git reset --hard a1b2c3d4e5
    ```

> **💡 Consejo de Senior:** Como regla de oro de la ingeniería de software: **nunca** uses `git reset` para eliminar o alterar commits que ya hayan sido enviados (*push*) a un repositorio compartido en GitHub o GitLab. Al reescribir el historial compartido, romperás el flujo de trabajo de tus compañeros. En su lugar, utiliza siempre `git revert`, lo que generará un commit seguro que deshace los cambios sin alterar la línea de tiempo histórica.
