# Glosario Técnico y Bibliografía Oficial

Para consolidar tu aprendizaje en **GitSOS**, hemos reunido en este documento todos los términos técnicos clave utilizados a lo largo de los módulos, acompañados de sus definiciones formales respaldadas por la documentación oficial. Al final, encontrarás la bibliografía y las fuentes de verdad utilizadas para construir esta plataforma educativa.

## 1. Glosario Técnico de Ingeniería de Software

### Conceptos de Arquitectura y Almacenamiento

*   **Directorio de Trabajo (*working directory*):** El directorio físico en el disco duro de tu computadora que contiene una copia de una versión específica del proyecto. Aquí es donde editas, creas y manipulas los archivos de tu código directamente antes de enviarlos a Git.
*   **Área de Preparación (*staging area* o *index*):** Un archivo temporal, administrado por Git y generalmente ubicado dentro del directorio `.git`, que registra y agrupa la información sobre los cambios específicos que vas a incluir en tu próxima confirmación (*commit*). También sirve como espacio de preparación de múltiples versiones (*stages*) durante un proceso de fusión desatendido o en conflicto.
*   **Repositorio Local (*local repository* o *Git directory*):** El corazón y la sección más importante de un proyecto Git. Contiene los metadatos y la base de datos de objetos comprimidos donde se almacena de forma inmutable todo el historial de versiones de tu proyecto.
*   **Repositorio Remoto (*remote repository*):** Una versión de tu proyecto alojada en un servidor en la nube (como GitHub o GitLab) o en otra máquina de la red. Permite realizar copias de respaldo de tu repositorio local e interactuar con los cambios de otros desarrolladores.
*   **Base de Datos de Objetos (*object database*):** Estructura interna de Git que almacena los datos de tu historial en cuatro componentes principales comprimidos:
    *   **Blobs (*blobs*):** Objetos de bajo nivel que contienen los datos y contenidos crudos de tus archivos (sin nombres ni metadatos de rutas).
    *   **Árboles (*trees*):** Objetos que apuntan a blobs y a otros árboles secundarios, recreando la estructura y jerarquía de carpetas y archivos de tu directorio de trabajo.
    *   **Confirmaciones (*commits*):** Objetos que referencian a un árbol raíz específico y a una lista de confirmaciones padre para representar un paso en la línea de tiempo del proyecto.
    *   **Etiquetas (*tags*):** Objetos opcionales que apuntan directamente a una confirmación para marcar un punto importante (como una versión del software).
*   **Suma de Comprobación SHA-1 (*SHA-1 checksum*):** Una cadena hexadecimal única de 40 caracteres (0-9, a-f) calculada en base al contenido de cada objeto en Git. Garantiza la absoluta integridad de los datos, haciendo imposible modificar un archivo sin que Git lo detecte.

### Comandos y Operaciones Diarias

*   **Comandos de Porcelana (*porcelain commands*):** Comandos fáciles de usar y orientados a la experiencia del desarrollador final, diseñados para las tareas cotidianas de control de versiones (ej. `git status`, `git add`, `git commit`).
*   **Comandos de Plomería (*plumbing commands*):** Comandos de bajo nivel utilizados internamente por Git para interactuar con la base de datos de objetos (ej. `git cat-file`, `git hash-object`). Tienen una sintaxis muy estable y son ideales para la creación de scripts.
*   **Confirmación (*commit*):** La acción y el resultado de tomar una "copia instantánea" (*snapshot*) del estado de tus archivos preparados en el índice y guardarlos permanentemente en la base de datos de tu repositorio local.
*   **Rama (*branch*):** Un puntero o referencia móvil de texto simple que apunta al commit más reciente de una línea de desarrollo independiente. En Git, las ramas son extremadamente rápidas, ligeras y casi instantáneas de crear.
*   **Fusión (*merge*):** El proceso técnico de integrar el historial de confirmaciones de una rama de desarrollo independiente dentro de otra rama activa.
*   **Conflicto de Fusión (*merge conflict*):** Situación que ocurre cuando dos ramas modifican de manera diferente la misma línea de un mismo archivo, impidiendo que Git realice una fusión automática. Requiere que un desarrollador limpie manualmente los marcadores antes de completar el commit de fusión.

### Colaboración en la Nube

*   **Bifurcación (*fork*):** Una copia completa de un repositorio de GitHub o GitLab que se crea en tu propia cuenta en la nube. Te permite experimentar y modificar el código libremente sin peligro de alterar el repositorio original.
*   **Solicitud de Incorporación de Cambios (*pull request*):** Concepto de colaboración nativo de **GitHub** mediante el cual informas a los mantenedores de un proyecto sobre los cambios que has subido a una rama y les pides formalmente fusionarlos en la rama principal.
*   **Solicitud de Fusión (*merge request*):** El equivalente colaborativo de la solicitud de incorporación de cambios pero nativo de la plataforma **GitLab**, permitiendo revisar y discutir el código antes de la fusión.
*   **Descarga de Datos (*fetch*):** Operación para descargar los últimos cambios, ramas e historial desde el servidor remoto hacia tu repositorio local sin alterar o fusionar nada en tu directorio de trabajo activo.
*   **Actualización Directa (*pull*):** Comando compuesto que realiza un fetch de metadatos remotos y los fusiona (*merge*) de forma automática en la rama activa en la que te encuentras posicionado.

## 2. Bibliografía y Fuentes Oficiales

Todo el contenido didáctico desarrollado en la plataforma **GitSOS** se apoya estrictamente en la literatura de referencia y la documentación técnica de los creadores y líderes del ecosistema de desarrollo de software:

### 1. Pro Git Book (2.ª Edición)
*   **Título:** *Pro Git* de Scott Chacon y Ben Straub.
*   **Propósito en GitSOS:** Es la fuente de verdad fundamental detrás de nuestro modelo mental. Proporciona los conceptos de almacenamiento en copias instantáneas (*snapshots*), la descripción del estado de tres zonas y los diagramas lógicos de la arquitectura inmutable de Git.
*   **Capítulos Clave Ingeridos:**
    *   *Capítulo 1: Inicio y Fundamentos de Git*.
    *   *Capítulo 2: Guardando cambios en el Repositorio y Trabajo con Remotos*.
    *   *Capítulo 3: Ramificaciones en Git (¿Qué es una rama?)*.

### 2. Manual de Referencia de Git
*   **Título:** *Git Reference Manual & User Manual* (Mantenido por Junio C Hamano y la comunidad de código abierto de Git).
*   **Propósito en GitSOS:** Estándar técnico utilizado para garantizar la precisión de cada comando de consola y variable de entorno. De aquí derivamos las explicaciones de la diferencia entre comandos de porcelana y de plomería, la seguridad del repositorio y el uso de firmas hash SHA-1.
*   **Secciones Consultadas:**
    *   *SINOPSIS y OPCIONES del núcleo de Git*.
    *   *Guía del Usuario de Conceptos Internos de Git*.

### 3. Documentación Oficial de GitHub
*   **Título:** *GitHub Docs Portal* (GitHub, Inc.).
*   **Propósito en GitSOS:** Base metodológica para explicar flujos de trabajo colaborativos modernos. Aporta las directrices de configuración de cuentas, autenticación mediante SSH e HTTPS, y la creación de flujos de integración y despliegue automatizado con **GitHub Actions**.
*   **Áreas Ingeridas:** *Código colaborativo y flujos de solicitudes de incorporación de cambios (Pull Requests)*.

### 4. Documentación Oficial de GitLab
*   **Título:** *GitLab Documentation Hub* (GitLab, B.V.).
*   **Propósito en GitSOS:** Utilizado como referencia para el desarrollo del flujo cooperativo avanzado y solicitudes de fusión (*Merge Requests*), además de la sintaxis estricta y flujos de configuración del archivo de automatización integrada en **GitLab CI/CD**.
*   **Secciones Consultadas:** *Get started with Git & GitLab CI/CD workflows*.
